## 一、选择题

### 1. 答案：**A**

- **解析**：类别不平衡时，准确率会被多数类"撑高"。一个把所有样本都判为多数类的模型，准确率可以高达 99%，却一个少数类都抓不住。

### 2. 答案：**A**

- **解析**：精确率 = TP/(TP+FP)，衡量"预测为阳性的人里，有多少是真阳性"（关心误报）。

### 3. 答案：**B**

- **解析**：召回率 = TP/(TP+FN)，衡量"真正的阳性里，有多少被找出来了"（关心漏报）。

### 4. 答案：**B**

- **解析**：F1 = 2×P×R/(P+R)，是精确率和召回率的**调和平均**，比算术平均更"惩罚"极端值。

### 5. 答案：**B**

- **解析**：AUC=0.5 表示模型的排序能力等同于**随机猜**（ROC 曲线是一条对角线）。AUC 越接近 1 越好；若 AUC<0.5，说明模型把方向搞反了。

### 6. 答案：**B**

- **解析**：交叉验证把数据切 K 份轮流做验证，取平均，避免单次划分的"运气"，得到更稳健的性能估计。

## 二、简单计算题

### 7. 三大指标

```
总数 = TP + FP + FN + TN = 90 + 10 + 20 + 80 = 200

准确率 = (TP + TN) / 总数 = (90 + 80) / 200 = 170/200 = 0.85

精确率 = TP / (TP + FP) = 90 / (90 + 10) = 90/100 = 0.9

召回率 = TP / (TP + FN) = 90 / (90 + 20) = 90/110 ≈ 0.818
```

**答案：准确率 0.850，精确率 0.900，召回率 0.818**

### 8. F1 分数

```
F1 = 2 × 精确率 × 召回率 / (精确率 + 召回率)
   = 2 × 0.9 × 0.818 / (0.9 + 0.818)
   = 1.4724 / 1.718
   ≈ 0.857
```

**答案：F1 ≈ 0.857**

> **提示**：F1 介于精确率和召回率之间，且更接近较小的那个（0.818），这正是"调和平均"惩罚极端值的特点。

## 三、中等计算题

### 9. 准确率陷阱

**计算：**

```
混淆矩阵：
实际患病（阳性）10 人，实际健康（阴性）990 人
模型全部预测"健康"（阴性）

TP = 0（没有查出任何病人）
FN = 10（10 个病人都被漏诊）
TN = 990（990 个健康人都"预测正确"）
FP = 0（没有误报）

准确率 = (TP + TN) / 总数 = (0 + 990) / 1000 = 99%
召回率 = TP / (TP + FN) = 0 / 10 = 0%
```

**分析：**

准确率高达 99%，看似优秀，但**召回率为 0%**——10 个癌症病人**全部漏诊**，一个都没查出来。对筛查场景来说，这是灾难性的失败。

**结论**：类别极度不平衡时（10:990），"把所有人判为多数类"就能拿到 99% 准确率。这正是正文"庸医的 99% 准确率"寓言的数学本质——**评价模型必须看混淆矩阵和召回率，不能只看准确率**。

### 10. 测试集只能评估一次

**原因：**

测试集的作用是**模拟"未知的真实世界"**，评估模型的泛化能力。它必须像"期末考试"，只能考一次。

**反复在测试集上调参的后果：**

如果你在测试集上反复调参、"偷看"成绩后不断改进，模型就会**间接地"记住"测试集**——测试集的信息通过你的调参决策泄漏进了模型。此时测试集分数会虚高，但**无法再反映真实的泛化能力**，上线后面对真正的未知数据可能表现很差。

**正确做法：**

- 训练集：训练模型
- 验证集（或交叉验证）：调超参数
- 测试集：**只在最后评估一次**，绝不回头改

> **易错点**：数据泄漏是新手最高频的错误之一。不仅要避免"测试集调参"，还要注意：**预处理（如标准化）必须在划分后、只在训练集上拟合**，否则同样会造成信息泄漏。
