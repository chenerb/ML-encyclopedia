# 模型部署：让模型"走出实验室"

## 概述

> **悬念提问**：模型在笔记本上跑得挺好，可一到线上就崩——响应太慢、内存爆掉、结果漂移。为什么"实验室里的好模型"和"生产环境的好模型"是两回事？答案在部署。

模型部署（Model Deployment）是把训练好的模型集成到实际生产系统、对外提供服务的过程。它是机器学习"最后一公里"，也是最容易被忽视的一环。

---

## 核心内容

### 1. 部署的常见方式

**① 在线服务（实时推理）**

模型封装成 API，实时响应请求：

```
用户请求 → API 网关 → 模型服务 → 返回预测
```

- 代表：Flask/FastAPI 封装、TensorFlow Serving、TorchServe
- 适合：要求实时响应的场景（推荐、风控）

**② 批量推理（离线）**

定期批量处理数据，结果存库：

- 适合：日报、离线打分、批量标注
- 优点：成本低、吞吐高

**③ 边缘部署**

模型跑在端侧（手机、摄像头、车载）：

- 代表：TensorFlow Lite、ONNX Runtime、TensorRT
- 适合：低延迟、隐私敏感、无网络场景

### 2. 部署的三大挑战

**① 性能优化**

- **模型压缩**：剪枝、量化（FP32 → INT8）、蒸馏
- **加速**：GPU/TPU、TensorRT、批处理

**② 工程可靠性**

- 服务监控、日志、容灾
- 模型版本管理、灰度发布、回滚

**③ 数据漂移（Concept Drift）**

线上数据分布随时间变化，模型逐渐失效：

- 监控：定期检查输入分布、预测分布
- 应对：定期重训、在线学习

### 3. 典型部署流程

```
训练模型 → 导出（ONNX/PB）→ 优化（量化/剪枝）→ 封装服务 → 测试 → 灰度上线 → 监控迭代
```

## 📖 寓言故事：从私房菜到连锁店

一位大厨在自家厨房烧得一手好菜（实验室里的好模型），名声远扬。

有人投资他开连锁店。可一开店，问题全来了：

- 自家做一道菜 5 分钟，店里客人排队半小时（推理太慢 → 优化加速）
- 菜谱全在脑子里，分店厨师学不会（模型不好迁移 → 导出标准化）
- 口味随季节变，老配方夏天还行、冬天就腻了（数据漂移 → 持续迭代）
- 一家店火了，十家店管理混乱（服务治理 → 监控、灰度、回滚）

大厨这才明白：**"会做菜"和"开好店"是两码事**。做菜是手艺，开店是工程——需要标准化菜谱、流水线、品控、供应链一整套。

他痛定思痛，把菜谱标准化、工序流水线化、口味定期调研调整……连锁店终于开成了。

> **寓意**：模型部署就是"从私房菜到连锁店"——**训练是"手艺"，部署是"工程"**。性能优化、服务治理、数据漂移监控，一样都不能少，模型才能真正创造价值。

## 实践建议

- **先明确场景**：实时还是离线？云端还是边缘？决定部署方式
- **模型要做优化**：量化、剪枝、蒸馏，把大模型变小变快
- **一定做监控**：输入分布、预测质量、延迟、资源
- **灰度发布 + 可回滚**：别一上线就全量替换
- **警惕数据漂移**：定期评估模型，必要时重训

## 总结

**关键要点：**
1. 部署是机器学习的"最后一公里"
2. 三种方式：在线、批量、边缘
3. 三大挑战：性能、可靠性、数据漂移
4. "会训练"≠"会部署"，工程能力是关键
